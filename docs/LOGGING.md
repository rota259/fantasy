# السجلات (Logging)

لما حاجة تبوظ عند يوزر، السجلات بتجاوب على تلات أسئلة: **إمتى؟** · **كان بيعمل إيه؟** · **الخطأ إيه؟**

النظام ده تطبيق لـ «Production Logging Playbook» على اللي عندنا فعلًا: أبلكيشن Flutter + Supabase + دالتين Edge. مفيش سيرفر بتاعنا ولا Docker، فالأجزاء الخاصة بيهم مكتوبة تحت في [اللي متطبّقش](#اللي-متطبقش-وليه).

## المكان الواحد

كل السطور بتتجمّع في جدول `app_logs` في Supabase، من 3 مصادر:

| المصدر | `service` | بيوصل إزاي |
|---|---|---|
| الأبلكيشن | `app` | `LogShipper` بيبعت دفعات لـ `log_events` |
| قاعدة البيانات | `db` | الدوال بتنادي `fn_log` (عمليات الأدمن بتتسجّل لوحدها) |
| الـ Edge Functions | `edge:push` · `edge:auth-phone` | `_shared/log.ts` — التحذيرات والأخطاء بس |

ومعاهم سجلات Supabase الجاهزة (Dashboard ← Logs): كل طلب للـ API بالكود والمدة، سجلات Postgres، سجلات Auth، ومخرجات الـ Edge Functions (كل سطورها JSON).

**القراية:** لوحة الأدمن ← «السجلات والأخطاء». محدش غير الأدمن يقدر يقرا الجدول، حتى من الـ API.

## شكل السطر

```json
{"timestamp":"2026-10-13T15:27:04.118Z","level":"error","service":"app","env":"prod",
 "version":"1.0.0+1","event":"http.error","session_id":"ses_a1b2c3d4e5f60718",
 "request_id":"req_9f2a1c0b7d3e4a55","user_id":"…","route":"POST /rest/v1/rpc/save_round_picks",
 "status":500,"duration_ms":1234,"error_type":"PostgrestException"}
```

| الحقل | معناه |
|---|---|
| `timestamp` | وقت الحدث UTC بصيغة ISO-8601 بالملّي ثانية. في الجدول: `client_ts` (الجهاز) و`ts` (السيرفر). |
| `level` | `debug` · `info` · `warn` · `error` · `fatal` |
| `service` / `env` / `version` | مين بعت السطر، وفي أنهي بيئة (`dev` · `staging` · `prod`)، ورقم الإصدار. |
| `event` | اسم ثابت بنقط، زي `auth.login.failed`. ده اللي بنبحث ونعدّ بيه. |
| `request_id` | رقم الطلب. بيتبعت للسيرفر في الهيدر `X-Request-ID`. |
| `session_id` | رقم عشوائي لكل مرة الأبلكيشن يتفتح. |
| `user_id` | بيتاخد من الجلسة في السيرفر، مش من اللي الأبلكيشن يبعته. |
| `route` / `status` / `duration_ms` | الطريقة والمسار (من غير أي قيم)، كود الرد، والمدة. |
| `error_type` / `error_stack` | اسم الخطأ والـ stack trace. |
| `fields` | أي تفاصيل زيادة — قيم بسيطة بس. |

## المستويات

| المستوى | يتستخدم لإيه | في النسخة المنشورة |
|---|---|---|
| `debug` | تشخيص وقت التطوير، وكل طلب ناجح | مقفول، ومبيتبعتش للسيرفر أبدًا |
| `info` | حدث طبيعي مهم: دخول، تسجيل، طلب السيرفر رفضه لإدخال غلط | شغّال |
| `warn` | حاجة غريبة اتعالجت: النت قطع، طلب بطيء، رفض صلاحية | شغّال |
| `error` | عملية فشلت ويوزر اتأثر | شغّال + تنبيه |
| `fatal` | خطأ محدش مسكه | شغّال + تنبيه |

**المستوى إعداد مش كود:**

- وقت البناء: `--dart-define=LOG_LEVEL=debug` (الافتراضي `debug` في التطوير و`info` في النسخة المنشورة).
- من غير نسخة جديدة: شاشة السجلات ← «مستوى السجلات». بيتطبّق عند كل يوزر أول ما يفتح الأبلكيشن.
- الـ Edge Functions: السر `LOG_LEVEL`، ومعاه `APP_ENV` (الافتراضي `prod`).

## استخدامه في الكود

Logger واحد بس: `lib/core/logging/app_log.dart`. ممنوع `print` أو `debugPrint` برّه.

```dart
AppLog.info('auth.login.success', fields: {'method': 'google'});
AppLog.error('lineup.save.failed', error: e, stack: st, fields: {'round': 12});
```

- أي كلام من اليوزر يتحط في `fields`، مش جوه اسم الحدث أو الرسالة.
- الخطأ يتسجّل مرة واحدة، في المكان اللي بيمسكه.
- إدخال غلط من اليوزر `info` أو `warn`، مش `error`.

اللي بيتسجّل لوحده من غير ما تكتب حاجة:

| إيه | الحدث |
|---|---|
| فتح الأبلكيشن (النسخة والمستوى) | `app.start` |
| أي خطأ محدش مسكه | `flutter.error` · `dart.uncaught` |
| كل طلب للسيرفر | `http.request` (debug) · `http.slow` · `http.rejected` · `authz.denied` · `http.rate_limited` · `http.error` · `http.unreachable` |
| الدخول والتسجيل وكلمة السر والخروج وحذف الحساب | `auth.*` |
| عمليات الأدمن (تغيير دور، حظر، إعدادات…) | `audit.admin.*` |
| الإشعارات | `push.sent` · `push.fcm.failed` · `push.forbidden` |
| المهام المجدولة | جدول `cron.job_run_details` (البداية والنهاية والنتيجة)، والفشل `job.failed` |

## ممنوع يتسجّل

كلمات السر (حتى الغلط)، التوكنات والـ JWT، أكواد التأكيد، هيدر Authorization، محتوى الطلب أو الرد، وأي رقم قومي أو بيانات دفع.

الحماية على مرحلتين، عشان غلطة في واحدة متسرّبش حاجة:

1. **في الأبلكيشن** (`log_redact.dart`): أي حقل اسمه فيه `pass` · `token` · `secret` · `apikey` · `authorization` · `cookie` · `otp` · `code` · `card` · `cvv` · `national` بيتشال. الإيميل بيبقى `a***@gmail.com` والرقم `010*****78`، وأي JWT في نص بيبقى `[token]`.
2. **في السيرفر** (`fn_log_clean` · `fn_log_mask`): نفس التنضيف تاني قبل التخزين.

المسار بيتسجّل من غير الـ query، وأي جزء شكله رقم تعريف أو اسم ملف بيبقى `:id`.

## البحث

من شاشة السجلات:

- **برقم الطلب:** اكتب `req_…` في البحث، أو افتح أي سطر ودوس «كل سطور الطلب ده».
- **أخطاء آخر ساعة:** فلتر «أخطاء»، والعدد في اللوحة فوق.
- **يوزر معيّن:** الصق رقم حسابه في البحث.
- **نوع خطأ:** دوس عليه في «أكتر الأخطاء».

ومن SQL Editor:

```sql
select ts, level, service, event, route, status, duration_ms, error_type, message
from app_logs where request_id = 'req_9f2a1c0b7d3e4a55' order by id;
```

```sql
select ts, event, error_type, route, status, user_id
from app_logs where level in ('error', 'fatal') and ts > now() - interval '1 hour' order by id desc;
```

## التنبيهات

`fn_log_watch` بتشتغل كل 5 دقايق (pg_cron: `khomasi-logs`). التنبيه إشعار لكل الأدمنز بيفتح شاشة السجلات، ومبيتكررش لنفس النوع قبل نص ساعة.

| التنبيه | الشرط |
|---|---|
| قفزة أخطاء | أخطاء آخر 5 دقايق أكتر من 5 أضعاف المعتاد، وعلى الأقل 10 |
| خطأ جديد | نوع خطأ أول مرة يظهر |
| مهمة مجدولة فشلت | تشغيلة فاشلة في `cron.job_run_details` في آخر 10 دقايق |
| تخمين كلمة سر | أكتر من 10 محاولات دخول على نفس الرقم في 5 دقايق |

**لو المهام المجدولة نفسها وقفت** مفيش حد يبعت التنبيه، فده بيظهر في لوحة السجلات: «مهام السيرفر واقفة من…» بالأحمر لو آخر نبضة أقدم من ربع ساعة.

## مدة الحفظ والحجم

- 30 يوم للتحذيرات والأخطاء، و14 يوم للـ `info`. بتتغيّر من `app_config`: `log_retention_days` (من 7 لـ 365).
- `debug` مبيتخزّنش في السيرفر.
- حدود الإرسال: 20 سطر في النداء، 60 كل 5 دقايق لليوزر، و200 في الدقيقة لكل الزوّار مع بعض.
- نفس الخطأ بيتسجّل 3 مرات بالكتير في الجلسة.
- لو النت قاطع: السطور بتستنى على الجهاز (آخر 30) وبتتبعت أول ما يرجع، حتى لو الأبلكيشن اتقفل.

## الاختبار

اختبارات آلية:

```bash
flutter test test/logging_test.dart
```

```bash
cd supabase/tests && npm test
```

الأولى بتتأكد من التنضيف وشكل السطر والمستويات. التانية من إن السيرفر بيشيل الأسرار، بياخد رقم اليوزر من الجلسة، بيطبّق الحدود، بيبعت التنبيه مرة واحدة، وبيمسح القديم.

**الاختبار الأخير على السيرفر الحقيقي** (بعد تشغيل `migrate_all.sql`): شغّل ده في SQL Editor، وبعدها افتح شاشة السجلات. لازم تلاقي السطر في أقل من دقيقة.

```sql
select public.fn_log('error', 'test.fake_error', 'تجربة السجلات', '{"by":"admin"}', 'db', 'req_test_0001');
```

## اللي متطبّقش وليه

| من الـ Playbook | الوضع |
|---|---|
| Collector (Vector / Fluent Bit) و Loki و Grafana | مش مطبّق. دول لسيرفرات وحاويات، وإحنا معندناش. البديل جدول `app_logs` وشاشة الأدمن. |
| OpenTelemetry (`trace_id`) | مش مطبّق. الطلب عندنا بيعدّي على خدمة واحدة، و`request_id` كفاية. |
| رجوع `X-Request-ID` في الرد | الـ Edge Functions بترجّعه. طلبات قاعدة البيانات بتعدّي على بوابة Supabase وهي اللي بتتحكم في الرد. |
| وصول الرقم لسجلات Supabase نفسها | الأبلكيشن بيبعته في كل طلب، بس متأكدتش إن بوابة Supabase بتعرضه في سجلاتها. المضمون إنه متسجّل عندنا في `app_logs`. |
| تخزين warm / cold لسنة | مش مطبّق. مرحلة واحدة 30 يوم. لو محتاج أرشيف: Supabase Log Drains (باقة مدفوعة). |
| تنبيه «السجلات وقفت» | بيظهر في اللوحة بس، مش إشعار. |
| سجلات audit متتعدّلش أبدًا | الأبلكيشن والأدمن ميقدروش يعدّلوا أو يمسحوا. صاحب قاعدة البيانات يقدر. |
| Dashboard فيه معدّل الطلبات | اللوحة فيها الأخطاء والطلبات الفاشلة وp95 وأكتر الأخطاء. المعدّل الكلي في Supabase ← Reports. |
